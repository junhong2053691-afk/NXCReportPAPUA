# 响应式 / 手机适配：决定（2026-11-05 grilling 定稿）

依据：[audit.md](audit.md)（巡检清单，A–E 编号沿用）。

## 目标

**每个员工只靠一部手机就能随时随地做完全部工作，不依赖电脑。**
operator 只能进 `/bank-accounts.html`（`server/index.js` 的页面守卫），所以「全部工作」=
**银行页的所有写操作在手机上可用**：审批/跳过待处理（含拆分调钱）、编辑/删除/恢复流水、调钱、
渠道新增/编辑/封禁/解封/使用中。admin 另有 16 页。

## 决定

| 项 | 决定 | 生效范围 |
|---|---|---|
| 最窄宽度 | 360px 下卡片与按钮不横滚；`min-width:320px` 兜底保留 | — |
| B 待处理 | 手机上每笔一张卡片：类型/金额/时间 → USER（完整）/TRANS ID → 控件竖排 → 「审批 / 跳过」大按钮 | ≤700 |
| C USER 列 | 允许换行，最多两行，不再省略号截断 | 全宽度 |
| D 银行页顺序 | 待处理工作条 → KPI → 流水；渠道列表默认折叠成一行 | ≤700 |
| 流水编辑 | 卡片 + 底部面板竖排表单；**复用 `data-f` input 与 `commitRow`/`readRow`**，不另写读取逻辑（`readRow`/`parseStatus` 会把显示文本反解析成 `status` 写库） | ≤700 |
| 弹窗 | 一律全屏，标题与保存/取消固定，中间滚动 | ≤700 |
| 底部标签栏 | 待处理（角标，复用现有计数）/ 流水 / 调钱 / 渠道 / 菜单（仅 admin）；admin 在别页点前四个先跳银行页 | ≤700 |
| 渠道排序 | 手机上隐藏拖拽把手，排序用电脑 | ≤700 |
| A 流水列宽 | NAME / BANK ACC / REMARK 收窄并允许两行，1366 一屏放下 | 桌面 |
| 报表 11 页 | `.table-wrap` 第一列 sticky，横滑仍可见行主体 | ≤700 |
| admin 写操作 5 页 | 支付设置、公司设置、Telegram 设置、账号管理、客户导出：逐页做手机版（卡片 + 底部面板） | ≤700 |
| 首页 | KPI 两列网格，净输赢占满一行 | ≤700 |
| 断点 | 旧断点不动；新规则只用 ≤700 / ≤1100 / 桌面三档 | — |
| 约束 | 除 A、C 外电脑端完全不变；新卡片里的租户数据一律 `translate="no"` | — |

## 交付顺序

每项单独提交，用户在手机上试过再做下一项。

1. 待处理卡片（B + C）
2. 弹窗全屏
3. 银行页手机排序 + 底部标签栏（D）
4. 流水卡片 + 编辑底部面板
5. 渠道列表平板横滚、手机隐藏拖拽把手（E）
6. 流水 1366 一屏（A）
7. 报表首列 sticky + 首页两列 KPI
8. admin 写操作 5 页
