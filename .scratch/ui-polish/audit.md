# UI 精修巡检（2026-11-09）

依据：`/impeccable critique + audit`，口径见 [DESIGN.md](../../DESIGN.md)「已知漂移」。
上一轮（`.scratch/ui-responsive/`）量的是**裁剪 / 横滚 / 截断**，这一轮量的是**尺寸一致性**：
同类元素是否一样大、字号是否落在刻度上、按钮里字和框的比例、页面骨架是否对齐。

**环境**：3200 端口的巡检实例（demo 库 + 种子数据：2 家公司、40 个客户、待审批 4 笔），admin 账号，暗色主题。
19 个导航页 × 1366 / 360，1920 抽查首页与 Telegram 设置。每页注入同一段测量脚本
（scratchpad `polish/measure.js`），截图人工看。

> ⚠️ 这个实例是今天早些时候启动的：**CSS / JS 是磁盘最新**，但 `server/index.js` 生成的页面骨架是旧版。
> 当日流水页因此多出一行已删掉的「当前公司读取中…」、少了银行列表。**当日流水 / 支付渠道的结论要在新实例上复核**。
> 截图里偶尔出现「半透明的卡片」是后台标签页里入场动画没跑完，不是样式问题，已排除。

## 结论先说

1. **整页层面没有坏**：19 页在 360 / 1366 下都没有整页横滚、没有越界。上一轮的手机适配都还在。
2. 「有的太大、有的太小」可以归成 **5 个根因**，按影响面排序：

| # | 根因 | 一句话 |
|---|---|---|
| **R1** | 电脑上的控件按手机触控尺寸做 | 电脑上按钮 40–44px 高、里面的字只有 11–12px：**框大字小**，是「太大」的主要来源 |
| **R2** | 字号没有刻度 | 一页里同时出现 8 / 9 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 …… 银行页的小标签掉到 8–9px，是「太小」的主要来源 |
| **R3** | 标题三层叠加 | 顶栏「NXC REPORT + 页名」→ 页内眉题 → 页内 H1，内容重复、中英混用，手机上 H1 被挤成两三行 |
| **R4** | 同一行控件高度不齐 | 工具栏里按钮 40 / 42、输入框 39 / 41 / 44 混排，底边对不齐，是「跑形」的主要来源 |
| **R5** | 宽屏不设上限 | 1920 下表单输入框拉到 1745px；卡片网格出现「6 个 + 3 个」的残行 |

## 详细问题

### R1 框大字小（电脑端，1366）

| 编号 | 位置 | 实测 | 说明 |
|---|---|---|---|
| A1 | 全站 `.btn-sm` | 40px 高 / 12px 字 | 所有页面的次要按钮。`style.css:663` 的 `.btn-sm` 本来叫「小号」却是 40px |
| A2 | 支付设置 STATUS / C STATUS 表的「保存 / 删除」 | 35 个按钮，40px 高 / **11px** 字 | 字占不到框高的 30%，看起来像空按钮 |
| A3 | 支付渠道行尾「编辑 / 封禁」 | 40px 高 / 11px 字；同一行 `Copy info` 30px 高 | 同一行三个按钮两种高度 |
| A4 | 当日流水接单区「审批 / 跳过」 | 40px 高 / 11px 字，「跳过」是描边、「审批」是实心 | 每行 4 笔就是 8 个大按钮，行高被撑到约 64px |
| A5 | 全站输入框 / 下拉 | 44px 高 / 12.5–14px 字 | 电脑上偏高；接单区里的日期时间被拆成上下两格，单行更高 |
| A6 | 页签 `.seg-btn` | 40px 高 / 12px 字 | 顾客分群、交易类型、排行排序 |

和它形成反差的是**流水工具栏 / 银行操作区压成了 32px**（`style.css` 里 `.sheet-toolbar .btn-sm`、`.bk-actions .btn-sm`），所以同一套「小按钮」在不同页面有 32 和 40 两种高度。

### R2 字号没有刻度

| 编号 | 位置 | 实测 | 说明 |
|---|---|---|---|
| B1 | 支付渠道（手机） | **8px ×12、9px ×13** | BANK BRANCH / NAME / BALANCE / COUNT 这些卡片小标签，手机上几乎看不清 |
| B2 | 支付渠道（电脑） | 9px ×13 | 同上 |
| B3 | 交易类型徽章 `.badge` / `.type-badge` | 10px（首页 10.5px） | 实时交易页 64 个徽章都是 10px |
| B4 | 表头 | 报表 11px，支付设置 / Telegram 10px，流水表 10–11px | 同是表头，三种大小 |
| B5 | 表格正文 | 12.5px | 不在任何刻度上；流水表又是 11px |
| B6 | 手机按钮字 | 16px，同一行 `Copy info` 13px | 支付渠道卡片里「Copy info / 编辑 / 封禁」三个按钮字号不一样大 |
| B7 | 每页的字号种类 | 电脑 9–11 种，支付渠道 11 种（9 / 10 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 15 / 18 / 20） | DESIGN.md 里定的是 11 档 token，实际一个都没用（使用率 1%） |

### R3 标题三层叠加

| 编号 | 位置 | 实测 | 说明 |
|---|---|---|---|
| C1 | 全站顶栏 | 「NXC REPORT」眉题 + 页名（18px） | 页内马上又是一个 24px H1，同一个名字说两遍 |
| C2 | 顶栏页名与 H1 不一致 | 月报页顶栏写 `REPORT`、H1 写「月报」；交易页「交易」vs「实时交易」；客户页「客户」vs「顾客列表」；Telegram 页「Telegram」vs「Telegram 设置」 | 用户分不清哪个是标题 |
| C3 | 首页 | 顶栏「总览」+ 眉题 `OPERATIONS OVERVIEW` + H1「今日 Command Center」 | 三层、中英混排；手机上 H1 33px 折成**三行** |
| C4 | 顾客列表（手机） | H1「顾客列表」被右侧说明挤成两行 | `.page-header` 手机上仍是左右排 |
| C5 | 支付设置（手机） | 顶栏「支付设置」+ H1「支付设置」上下紧挨 | 最直观的重复 |
| C6 | 支付渠道 | 没有 H1，用的是 `ALL CHANNELS / 全部渠道` 汇总块 | 和其他页的页头结构不一致 |

| D4 | 勾选框 | 13 / 14 / 16 / 18 / 22px 并存 | 支付设置对平勾选 13px、Telegram 开关 16px、导出勾选 18px |
| D5 | 支付渠道页签（手机） | 34px 高 | 低于 44px 触控线，旁边按钮都是 44 |
| D6 | 月报「月 / 年」切换（手机） | 39 × 44 | 窄 |

## 留给 /grill-with-docs 决定的问题

1. **控件高度**（R1 / R4，上次你选了「先巡检再定」）：电脑端统一成几档？建议「标准 36 / 紧凑 32」两档，≤700 才放大到 44。
2. **字号刻度**（R2）：DESIGN.md 里已有 11 档 token，是直接启用，还是收成更少的档（例如 11 / 12 / 13 / 14 / 16 / 20 / 24 / 32）？最小字号定多少（建议 11px，手机 12px）？
3. **标题**（R3）：顶栏还要不要显示页名？建议顶栏只留状态与开关，页名只在 H1 出现一次；首页 H1 改成纯中文。
4. **宽屏**（R5）：表单类页面（Telegram / 公司设置 / 支付设置）要不要限制最大宽度（例如 960px）？
5. **银行两页**：先在新实例上复核当日流水与支付渠道，再决定 A3 / A4 / B1 怎么改。
